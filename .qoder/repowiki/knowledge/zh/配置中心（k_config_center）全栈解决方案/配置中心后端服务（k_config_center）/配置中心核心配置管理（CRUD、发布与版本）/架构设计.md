模块采用经典的 Controller → Service → Repository → Entity 四层结构，依赖方向单向向下：
- Controllers（Controllers/）：基于 ASP.NET Core [ApiController] 暴露 /api/configurations、/api/configuration-groups、/api/namespaces、/api/environments、/api/operation-logs 等端点，仅负责参数接收、调用 Service 并以 ApiResponse 包装响应。
- Services（Services/）：按业务域拆分，ConfigurationService 处理配置的增删改查与版本查询；PublishService 专管发布/回滚/下线等事务型操作；ClientConfigurationService 面向客户端读取；OperationLogService/EnvironmentService/NamespaceService/ConfigurationGroupService 对应各自领域。
- Repositories（Repositories/）：基于 SqlSugar 直接操作数据库，ConfigurationRepository 集中了当前态表与五表联查（namespace/environment/group/configuration/configuration_version），并通过 DatabaseTransactionRunner.ExecuteAsync 在 ISqlSugarClient 单例的事务上下文中执行跨表动作，Service 层不直接接触 ISqlSugarClient。
- Entities（Entities/）：SqlSugar 实体类（ConfigCenterConfiguration、ConfigCenterConfigurationVersion、ConfigCenterNamespace、ConfigCenterEnvironment、ConfigCenterConfigurationGroup、ConfigCenterOperationLog），使用 SugarTable/SugarColumn 映射 PostgreSQL 列名，包含软删除字段 deleted_at。
- Models（Models/）：Requests/Responses 作为 API 入参出参；Domain/ 存放 record 形态的业务数据（ConfigurationData、ConfigurationVersionData、BasicDimensionData、CommonData），是 Repository 与 Service 之间的契约，避免 Entity 泄漏到上层。

关键架构约束：
- 版本号原子递增通过 SQL UPDATE ... RETURNING 在行锁上串行化，并发冲突由唯一约束兜底转 30004。
- 发布/回滚事务内顺序执行「版本号 +1 → 写不可变版本快照 → 切换 published_version_id → 写审计日志」，任一失败整体回滚。
- md5 由服务端 OperationHelper.ComputeMd5 计算，不信任前端传入值。
- 所有写操作通过 OperationLogRepository 记录操作人、客户端 IP 与资源维度信息。
