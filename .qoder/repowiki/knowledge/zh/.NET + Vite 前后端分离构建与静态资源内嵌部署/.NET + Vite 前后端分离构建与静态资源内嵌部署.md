## 1. 使用的构建系统

本项目采用**前后端双工程、单一应用部署**的构建模式：
- **后端**：基于 `Microsoft.NET.Sdk.Web`（.NET 10.0）的 ASP.NET Core Web API，通过 Visual Studio 解决方案文件 `k_config_center.sln` 管理项目，使用 NuGet 包管理依赖。
- **前端**：基于 React + TypeScript + Vite 的单页应用，通过 `package.json` 脚本驱动开发、类型检查与生产构建。
- **无容器化/CI**：仓库中不存在 Dockerfile、docker-compose、GitHub Actions、GitLab CI、Makefile 或自定义 build 脚本；发布流程未纳入版本控制。

## 2. 关键文件

| 文件 | 作用 |
|---|---|
| `k_config_center.sln` | 解决方案文件，定义 Debug/Release 两种配置 |
| `k_config_center/k_config_center.csproj` | .NET 项目文件，声明 TargetFramework、NuGet 依赖（Npgsql、SqlSugarCore、Swashbuckle.AspNetCore） |
| `web/package.json` | 前端构建脚本：`dev`、`build`（先 `tsc --noEmit` 再 `vite build`）、`preview` |
| `web/vite.config.ts` | Vite 配置：别名 `@` → `src`、开发服务器端口 9001、代理 `/api` 到 `localhost:9002`、构建产物输出至 `../k_config_center/wwwroot` |
| `k_config_center/Properties/launchSettings.json` | VS/`dotnet run` 启动配置，HTTP 端口 9002，HTTPS 端口 7281/9000 |
| `k_config_center/appsettings.json` / `appsettings.Development.json` | 运行时配置（数据库连接等） |

## 3. 架构与约定

### 后端构建
- 目标框架固定为 `net10.0`，启用 Nullable 和 ImplicitUsings。
- 生成 XML 注释供 Swagger 展示接口文档，并通过 `NoWarn=1591` 抑制成员缺注释告警，保证构建零警告。
- 仅一个项目，无多项目引用，构建命令即 `dotnet build` / `dotnet publish`。

### 前端构建
- 开发：`npm run dev` 启动 Vite 开发服务器（端口 9001），通过反向代理将 `/api` 请求转发到后端 `http://localhost:9002`，实现同源调试。
- 构建：`npm run build` 先执行 `tsc --noEmit` 进行纯类型检查，再通过 `vite build` 打包静态资源。
- 产物输出目录为 `../k_config_center/wwwroot`，并清空旧产物（`emptyOutDir: true`），使前端静态文件直接由 ASP.NET Core 托管。

### 部署形态
- **单一应用部署**：Vite 构建产物被复制到后端项目的 `wwwroot` 目录，ASP.NET Core 同时提供 API 与静态页面，无需独立 Nginx 或前端服务。这是本仓库最核心的部署约定。
- 环境变量通过 `launchSettings.json` 中的 `ASPNETCORE_ENVIRONMENT` 区分 Development。

## 4. 约定与约束

- **端口约定**：前端开发服务器默认 9001，后端默认 9002，二者在 `vite.config.ts` 中硬编码关联，修改任一需同步更新另一处。
- **API 路径约定**：前端通过 `/api/*` 前缀访问后端，Vite 代理规则与后端路由前缀保持一致。
- **构建顺序**：前端构建必须先于后端发布，因为 `wwwroot` 需在 `dotnet publish` 时已存在最新静态资源。
- **无跨环境构建矩阵**：解决方案仅定义 Debug/Release 两种平台配置，无针对多目标框架或多环境的差异化构建逻辑。
- **无自动化流水线**：未发现任何 CI/CD 配置文件，本地手动执行 `npm run build` 后再 `dotnet publish` 是已知流程。
- **依赖锁定**：前端使用 `package-lock.json` 锁定 npm 依赖版本；后端通过 NuGet 包版本显式声明在 `.csproj` 中。
