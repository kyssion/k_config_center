# 前端方案（配置中心管理界面 Portal）

> 定位：纯前端视角的技术方案。
> 配套文档：`./项目整体架构设计.md`（顶层架构与部署）| `./后端方案.md`（接口定义与后端实现）| `../设计文档/配置中心设计文档.md`（领域模型）

---

## 1. 背景与页面诉求

配置中心的数据层级模型（命名空间 → 环境 → 配置组 → 配置项 → 版本快照）与发布/回滚机制已在设计文档中定稿。为了让配置的日常维护脱离直接操作数据库或裸调 API，需要为配置中心增加**管理界面（Portal）**能力。

Portal 页面清单：

| 页面 | 诉求 |
|------|------|
| 命名空间管理 | 命名空间的增删改查与启用/禁用 |
| 环境管理 | 命名空间下环境（dev/test/staging/prod）的增删改查、排序与启用/禁用 |
| 配置组管理 | 环境下配置组的增删改查与启用/禁用 |
| 配置列表与编辑 | 配置项列表（状态、未发布变更标记）；多格式内容（text / json / yaml / properties / xml / toml）编辑，具备语法高亮与基础校验 |
| 版本历史与 Diff | 查看配置项全部历史版本快照，任意两个版本（或当前编辑态与已发布版本）之间的差异对比 |
| 发布 / 回滚 | 将草稿内容发布为新版本，或以历史版本内容生成新版本回滚，配合「有未发布变更」标记 |
| 操作审计 | 按操作人 / 时间范围检索操作日志，各维度归属信息随列表展示 |

## 2. 候选方案对比与选型结论

| 方案 | 技术组合 | 优点 | 缺点 | 适用场景 |
|------|----------|------|------|----------|
| 方案一 | 前后端分离 SPA：Vue 3 + Element Plus | 生态成熟、中文资料丰富、组件覆盖全面；模板语法上手门槛低 | 需要引入 Node 工具链；中后台高阶封装（如 ProTable 一类）不如 React 生态完整 | 团队以 Vue 技术栈为主、追求快速上手的中后台项目 |
| 方案二 | 前后端分离 SPA：React 18 + Ant Design 5 | 生态同样成熟；AntD ProComponents（ProTable/ProForm）对 CRUD 类中后台页面提效明显；TypeScript 支持一流；Monaco、Diff 等编辑器周边组件最丰富 | 需要引入 Node 工具链；JSX 心智模型对纯后端团队略有门槛 | 中后台管理系统的主流选择，页面以表格 + 表单 + 编辑器为主的场景 |
| 方案三 | Blazor（Server 模式 + MudBlazor） | 纯 C# 技术栈，.NET 团队零前端成本上手最快；与后端共用模型类型 | 组件生态明显弱于 Vue/React；富文本/代码编辑器等复杂组件多依赖 JS 互操作；Server 模式依赖常连接，弱网体验差 | 全员 .NET、界面复杂度中低、不想维护双技术栈的团队 |
| 方案四 | Razor Pages + htmx 轻量方案 | 架构最简单，无独立前端工程，部署零额外成本 | 富交互页面（代码编辑器、版本 Diff、多面板联动）实现吃力，可维护性随交互复杂度快速恶化 | 页面以静态展示 + 简单表单为主的小型工具站 |

**结论：选定方案二 —— React 18 + TypeScript。UI 组件层原选 Ant Design 5，2026-09 整体替换为 Tailwind CSS v4 + shadcn/ui（见下文技术栈清单与变更日志）。**

理由：配置中心 Portal 的核心页面高度依赖「表格 + 表单 + 代码编辑器 + Diff 视图」，React 生态在这几类组件上的成熟度与可组合性最好（@monaco-editor/react、react-diff-viewer-continued 均为开箱即用）。UI 框架替换的动机：shadcn/ui 的组件源码直接拷入仓库（`src/components/ui/`）可读可改、无黑盒依赖；Tailwind 工具类与类型系统对 AI 辅助开发友好；同时去掉 antd 及其传递依赖（dayjs、rc-* 系列）显著减小包体。

## 3. 技术栈清单

| 类别 | 选型 | 说明 |
|------|------|------|
| 构建工具 | Vite | 开发启动快、配置简单，内置 dev 代理能力 |
| 语言 | TypeScript | 与后端 Response/Request 模型对齐，减少接口联调错误 |
| 样式方案 | Tailwind CSS v4（`@tailwindcss/vite` 插件，CSS-first 无 tailwind.config） | 工具类样式；设计令牌以 CSS 变量定义在 `src/index.css`（shadcn 约定） |
| UI 组件库 | shadcn/ui（组件源码在 `src/components/ui/`，基于 Radix UI 原语） | Button/Input/Select/Dialog/Sheet/Badge/Tooltip 等基础件；源码归仓库所有可自由修改 |
| 图标 | lucide-react | 替代 @ant-design/icons |
| 轻提示 | sonner | 替代 antd message，全局 `<Toaster />` 挂在 main.tsx |
| 路由 | react-router-dom v6 | 声明式路由，配合布局组件实现侧边栏导航 |
| 状态管理 | 无全局状态库 | 页面级筛选改版后不再有全局命名空间/环境上下文，筛选条件由各页面自持（zustand 已移除） |
| HTTP 客户端 | Axios（可选 TanStack Query） | Axios 拦截器统一处理错误提示与响应解包；数据缓存/重试等诉求增强时可引入 TanStack Query |
| 代码编辑器 | @monaco-editor/react + monaco-editor（本地打包，`utils/monacoSetup.ts`） | VS Code 同源内核，原生支持 json/yaml/xml 等语法高亮；编辑页路由懒加载，Monaco 拆为专属 chunk |
| 版本对比 | react-diff-viewer-continued | 双栏/单栏 Diff 视图，用于版本历史对比 |
| YAML 解析 | js-yaml | yaml 内容校验（load）与格式化（dump），供格式化器注册表使用 |
| XML 格式化 | xml-formatter | xml 内容美化（校验用浏览器原生 DOMParser，不额外引库） |
| 动画 | tw-animate-css | Dialog/Sheet/Popover 等浮层的进出场动画工具类 |

各目录职责：

- **api/**：所有请求经由 `http.ts` 的 Axios 实例，拦截器统一弹出错误提示并解包响应体，页面代码只关心业务数据；`types.ts` 与后端接口模型保持字段一致（模型定义参见 `./后端方案.md`），如 `ConfigurationResponse` / `EnvironmentResponse` / `ConfigurationGroupResponse` / `OperationLogResponse` 同步后端联表冗余的维度名称 / 业务 key 可选可空字段（维度列「名称 + key」展示用，见 `./后端方案.md` 7.2）；
- **router/**：集中式路由表，主布局作为父路由，各页面作为子路由嵌套渲染；
- **layouts/**：全局唯一的主布局（侧边栏 + 顶栏 + 内容区），页面组件不关心导航结构；
- **pages/ 按资源分目录**：与后端接口资源一一对应，便于前后端对照维护；筛选条件（命名空间/环境等）为页面级状态，由各页面自持，无跨页面共享上下文；
- **components/**：跨页面复用的业务组件（页面容器、表单抽屉、内容预览、可复制文本、维度单元格、格式选择、格式标签、状态标签、列配置按钮、可拖拽表头、Diff 视图）；
- **hooks/**：与 UI 无关的通用逻辑封装（表格请求、列配置持久化、轮询）；
- **utils/**：无 React 依赖的纯工具函数（剪贴板复制、配置内容格式化器注册表）。

## 5. 页面与路由设计

### 5.1 路由规划

| 路由路径 | 页面 | 说明 |
|----------|------|------|
| `/` | 重定向 | 重定向到 `/configuration` |
| `/namespace` | NamespaceList | 命名空间管理 |
| `/environment` | EnvironmentList | 环境管理（页面内按命名空间可选筛选） |
| `/group` | GroupList | 配置组管理（页面内按命名空间/环境可选筛选） |
| `/configuration` | ConfigurationList | 配置项列表（页面内五维可选组合筛选） |
| `/configuration/:id/edit` | ConfigurationEditor | 配置编辑（Monaco） |
| `/configuration/:id/versions` | VersionHistory | 版本历史与 Diff、回滚 |
| `/audit` | OperationLogList | 操作审计 |

所有页面路由挂在 `MainLayout` 布局路由之下；浏览器直接访问深层路由时由后端兜底返回 index.html（参见 `./项目整体架构设计.md` 部署机制）。

### 5.2 布局与页面级筛选

- **MainLayout**：自绘 flex 布局（无组件库布局件），左侧为侧边栏导航（NavLink：命名空间 / 环境 / 配置组 / 配置 / 审计，激活项品牌蓝高亮），顶栏 = **当前页面标题（左）+ API Key 输入框 + 操作人输入框（右）**，不再放置任何全局筛选控件；
- **页面级筛选取代全局上下文**：原「顶栏命名空间/环境选择器 + useScopeStore 全局上下文 + ScopeEmpty 空态」方案已下线——命名空间/环境等过滤条件下沉为各页面独立的筛选区状态（规范见 5.5），**无筛选条件即查询全部**，页面进入即可用，无「先选上下文」前置步骤，也不再需要空态引导组件；
- **操作人来源**：顶栏操作人输入框的值持久化到 localStorage（key: `operator`），缺省 `portal`；写操作的请求头注入方式见第 6 章。

### 5.3 各页面功能点

- **NamespaceList**：表格展示名称 / namespace_key / 描述 / 状态（名称列前置于 Key 列，见 5.6）；关键字筛选；新建与编辑走 FormDrawer；启用/禁用切换；
- **EnvironmentList**：环境列表（命名空间筛选可选，不选即全部，点「查询」生效，见 5.5），含 sort_order 排序；「所属命名空间」列用 DimensionCell 展示名称 Tag + 业务 key（名称与 key 由后端联表冗余返回，见 5.4 色彩体系）；增删改走 FormDrawer；
- **GroupList**：配置组列表（命名空间/环境筛选均可选，点「查询」生效，见 5.5）；命名空间/环境列用 DimensionCell 展示名称 Tag + 业务 key（名称与 key 由后端联表冗余返回）；增删改走 FormDrawer；点击组可跳转到该组的配置列表；
- **ConfigurationList**：**五维可选组合筛选**（命名空间/环境/配置组三级级联 + 状态 + Key 关键字，全不选即全量，点「查询」生效，见 5.5）的配置项表格，展示命名空间 / 环境 / 所属配置组（三列 DimensionCell：名称 Tag + 次行 key code 框，key 缺失时兜底显 #id，名称与 key 均由后端联表冗余返回）/ key / 内容（当前编辑态 content，ContentPreview 单行截断 + 悬浮预览）/ 格式（FormatTag 着色）/ 状态（StatusTag 着色）/ 最新版本号 / 「有未发布变更」标记（由服务端算好返回），配置组名称列前置于 Key 列（见 5.6）；新建配置抽屉的「配置值」字段在 `canFormat` 格式下提供「校验并格式化」入口（注册表 `validate` 失败提示具体错误，通过则美化回写，见 5.4 工具函数）；行操作：详情（只读抽屉，见 5.6）、编辑、发布、版本历史，下线/删除收纳进「更多」菜单；
- **ConfigurationEditor**：Monaco 编辑器按 format 切换语言高亮；保存（写草稿并重算 md5）与发布（弹窗填变更备注）两个动作分离；保存前的前端校验统一走格式化器注册表的 `validate`（json 完整语法校验、yaml 用 js-yaml 解析校验、xml 用 DOMParser、properties/toml 行级校验、text 恒合法，详见 5.4 工具函数；另 json 格式空内容单独拦截）；可用 `usePolling` 探测他人发布导致的内容变更并提示刷新；
- **VersionHistory**：版本列表（版本号、变更类型、备注、操作人、时间）；任选两个版本 Diff，或「当前编辑态 vs 已发布版本」Diff；每个历史版本提供「回滚到此版本」入口，二次确认后调用回滚接口；
- **OperationLogList**：按操作人（模糊匹配）/ 时间范围检索操作日志（检索表单收敛后固化，不再提供命名空间/环境/配置组/配置项/操作类型筛选），detail 字段展开查看变更详情；命名空间 / 环境 / 配置组 / 配置项四个维度列用 DimensionCell 展示关联资源的名称 + key（配置项无显示名称只显 key 行；名称与 key 由后端批量回查冗余返回，历史日志缺失的上级维度由后端逐级反推回填，已软删除资源也能回显，见 `./后端方案.md` 7.2；日志未关联该维度时显「-」）。

删除交互统一约定：各列表页（命名空间 / 环境 / 配置组 / 配置项）的删除操作均为软删除，由后端保证（参见 `./后端方案.md` 8.4）；界面需二次确认（AlertDialog）后再调用删除接口。

其余交互统一约定（UI 现代化改版后固化）：

- **操作列收纳**：行操作列只直接展示高频操作（控制在 4 个以内，如 ConfigurationList 直接展示详情/编辑/发布/版本历史），低频/危险操作收纳进 `DropdownMenu`「更多」菜单（如 ConfigurationList 行操作中的下线/删除）；
- **危险操作**：统一红色样式 + 二次确认——页面级 AlertDialog（删除/下线/脏表单关闭确认），Dropdown 菜单项点击后弹出同款 AlertDialog；
- **表格与表单容器**：列表统一 `DataTable`（`pagination.pageSize = 10` 含页容量选择与总数显示；窄窗口下 `min-w-max` 横向滚动而非内容越界溢出容器）；新建/编辑统一 FormDrawer（`width=480`，新建配置 640），发布（填备注）/回滚等确认类 Dialog 保留；
- **表单实现**：受控组件（useState 持有 values/errors/dirty）+ `FormField` 统一排版，提交前手动校验必填项并在字段下方红字提示——不引入表单库；
- **编辑器页布局**：「顶部工具条 Card（返回 + 配置 key + 未发布变更标记 + 格式切换/操作按钮组）+ 左侧配置信息卡（固定宽 320，InfoRow 键值对，字段口径对齐配置详情抽屉：配置 ID / 状态 / 命名空间 / 环境 / 所属配置组（DimensionCell）/ 配置项 Key（CopyableText）/ 保存格式（FormatTag，为服务端已保存格式，与工具条上本地编辑格式在未保存时可能不同）/ 当前 md5 / 生效版本 / 生效 md5 / 最新版本 / 发布时间 / 创建人 / 创建时间 / 最后修改人 / 更新时间 / 标签 / 配置说明）+ 右侧 Monaco 编辑器 Card（flex 自适应）」三段式布局；「格式化」按钮由注册表 `canFormat` 驱动展示（json/yaml/xml/properties 可格式化，toml/text 隐藏入口），先 `validate` 后 `format`，校验失败提示具体错误且不改动内容，纯前端处理不发请求；
- **版本历史**：生效版本在版本号列前置「生效中」绿色圆点 Badge 标识；「对比所选两个版本」按钮在未勾选满两个版本时禁用，并用 `Tooltip` 说明原因（`span` 包裹以保证 disabled 按钮上仍可触发提示），已勾选满两个版本后禁用其余行的勾选。

**工具函数**：

- **copyToClipboard** `(text: string) => Promise<boolean>`（`utils/clipboard.ts`）：剪贴板复制统一入口——优先 `navigator.clipboard.writeText`（需安全上下文），不可用或失败时降级 `document.execCommand('copy')`（临时 textarea，fixed + 透明不扰动布局，用完即移除）；返回是否复制成功，**工具内不弹提示**，由调用方（CopyableText / ContentPreview / 配置详情抽屉）根据结果用 sonner toast 反馈；
- **getFormatter** `(format: string) => ContentFormatter`（`utils/formatters.ts`）：配置内容格式化器注册表——六格式（text/json/yaml/properties/xml/toml，与后端 format 字段取值一致）各注册 `{ canFormat, validate, format }`：`validate` 返回 null 表示合法、否则返回错误描述；`format` 失败一律回退原文；`canFormat=false` 时 UI 隐藏格式化入口。各格式行为：json（`JSON.parse` 校验 + 2 空格缩进美化）/ yaml（js-yaml `load` 校验，错误信息自带行号，`dump` 美化；空内容格式化保持原样返回，不输出 null）/ xml（DOMParser 校验 + xml-formatter 2 空格缩进美化）/ properties（行级校验：空行与 `#`/`!` 注释跳过，其余须含 `=` 或 `:`，支持行尾 `\` 续行——续行中的行不要求含 `=`/`:`；美化仅去行尾空白与首尾空行，不破坏续行反斜杠）/ toml（仅行级校验：允许 `[section]`/`[[array]]` 与含 `=` 的键值行，`canFormat=false` 不支持美化）/ text（不校验不格式化：恒合法、原样返回）；未注册格式返回 text 同款兜底器。消费方：ContentPreview / 配置详情抽屉（format）、新建配置抽屉「校验并格式化」与编辑器「格式化」按钮（canFormat + validate + format）、编辑器保存前校验（validate）。

### 5.5 筛选区规范

页面级筛选改版后固化的筛选区约定（各列表页统一遵循）：

- **位置与形态**：筛选区位于 PageContainer 内容区顶部，一行 flex wrap（`mb-4`）排布筛选控件，无独立筛选 Card；
- **筛选行为（手动触发）**：筛选控件（`FilterSelect` 下拉 / 关键字输入框）变化只更新页面内的**草稿条件**，不触发列表请求；点筛选区「查询」按钮（或关键字输入框回车）才将草稿快照为**已生效条件**并重载列表（列表 fetcher 只依赖已生效条件；快照每次为新对象，条件未变时点查询也会刷新一次），「重置」清空草稿与已生效条件恢复全量；下拉清空统一为 FilterSelect 头部固定「全部」选项（Radix Select 不支持空值/allowClear 的等价实现），**无筛选条件即查询全部**，不存在必选前置条件；关键字的生效方式按页区分——ConfigurationList 随查询参数走服务端检索，EnvironmentList / GroupList 为已生效关键字的前端本地过滤；例外：NamespaceList 无下拉筛选仅关键字本地过滤（输入即过滤）；OperationLogList 为「查询/重置」提交模式（操作人 + 时间范围），与上述行为一致，时间范围用两个原生 `datetime-local` 输入框（替代 antd RangePicker，免去 dayjs 依赖）；
- **级联约定**：存在层级关系的筛选（如 ConfigurationList 的命名空间 → 环境 → 配置组）上级变化时清空下级选中值，下级选项数据源按上级过滤（上级未选则全量）——级联只影响草稿与下拉选项，同样不触发列表请求；
- **下拉实时刷新**：所有维度下拉（命名空间/环境/配置组，含筛选区与表单内）通过 Select 的 `onOpenChange` 在展开时按当前级联参数重新请求选项数据，保证其他页面新增后选项不陈旧；不加防抖与缓存；
- **分页**：列表统一客户端分页（DataTable 内置），`pageSize: 10` 起步 + 页容量选择（10/20/50/100）+ 「共 N 条」+ 数字页码（VersionHistory / OperationLogList 为服务端分页，传 total/onChange 受控翻页）；
- **表单入口**：新建/编辑统一走 FormDrawer；发布（填变更备注）等确认类弹窗保留 Dialog。

### 5.6 名称前置与配置详情抽屉规范

「名称前置与视觉精修」改版后固化的列序与详情展示约定：

**名称前置于 Key**（四个列表页统一）：

- **列顺序**：名称类列统一排在 Key 列之前——NamespaceList / EnvironmentList / GroupList 均为「名称 → Key」；ConfigurationList 为「所属配置组（名称 Tag）→ 配置项 Key」；意图是人读名称优先，机读标识退居其后；
- **Key 列展示**：四个列表页的 Key 列统一用 `CopyableText` 的 `code` 样式渲染（等宽代码观感 + 一键复制）；
- **表单字段顺序**：与列序一致，名称类字段排在 Key 字段之前——命名空间/环境/配置组表单均为「名称 → Key → 其余字段」，新建配置表单为「配置组 → 配置项 Key → 格式/配置值/说明」。

**配置详情抽屉**（ConfigurationDetailDrawer `{ open, record, onClose, onEdit }`）：

- **数据来源**：直接复用列表行数据（`ConfigurationResponse`，命名空间/环境/配置组名称与业务 key 由后端联表冗余返回，见 `./后端方案.md` 7.2），打开抽屉**零额外请求**；
- **只读定位**：无表单无脏检测，用普通 Sheet（`max-w-[560px]`）而非 FormDrawer；键值对网格（label 灰底、带边框）展示配置 ID / 状态（StatusTag）/ 命名空间 / 环境 / 所属配置组（三者均为 DimensionCell：名称 Badge + 次行 key code 框，key 缺失时兜底显 #id，见 5.4 色彩体系）/ 配置项 Key（CopyableText code）/ 格式 / 最新版本 / 最后修改人 / 创建时间 / 更新时间 / 配置说明；
- **配置值区块**：格式化后（注册表 `format`，失败回退原文）的只读代码块（灰底 `pre`，等宽字体，限高滚动），超 5000 字符截断展示并提示进编辑器查看；「复制全部」复制格式化后的完整内容，不受展示截断影响；
- **编辑入口**：抽屉底部「编辑配置」主按钮，通过 `onEdit` 交回列表页关闭抽屉并跳转编辑器页（`/configuration/:id/edit`），抽屉内不提供任何写操作。

### 5.7 列配置持久化约定

列表升级改版后，六个列表页统一接入「列显隐 + 宽度覆盖」配置能力（`useColumnSettings` hook + 筛选区右侧的 `ColumnSettingButton`，宽度另支持表头拖拽调整）：

- **localStorage key 规范**：`column-settings:${pageKey}`，各页 pageKey 固定为：namespace-list / environment-list / group-list / operation-log-list / configuration-list / version-history（版本历史页于拖拽调宽轮新接入列配置）；
- **操作列强制显示**：key 为 `'action'` 的操作列不参与配置——始终展示，不出现在设置面板的可配置清单中，也不参与拖拽调宽（不注入拖拽回调，表头退化为普通单元格）；
- **列宽拖拽调整**：非操作列表头右缘渲染 8px 拖拽手柄（`ResizableHeaderCell`），基于指针事件 + 指针捕获实现（`setPointerCapture` 保证移出手柄后 move/up 事件不丢失），零第三方依赖；最小宽度 60（`MIN_COLUMN_WIDTH`，与设置面板 InputNumber 的 min 对齐）；拖动过程中仅更新内存态做实时反馈，松手才写入 localStorage（避免高频写盘）；拖拽与设置面板 InputNumber 共用同一份宽度配置，任一侧修改另一侧即时同步；
- **列 key 取值**：列定义的显式 `key`（DataTableColumn 必填，页面统一定义）；
- **容错**：读取时 JSON 解析失败视为无配置；写入失败（localStorage 不可用）静默降级为仅内存态；宽度覆盖仅接受不低于下限的有限数值，存储被改坏（负数/NaN）时按无覆盖处理；「恢复默认」清空内存态并移除存储项；
- **接入方式**：页面把列定义交给 `useColumnSettings(pageKey, columns)`，返回的 `mergedColumns` 直接交给 DataTable（非操作列注入 `headerResize` 属性，DataTable 将表头渲染为 ResizableHeaderCell 并透传宽度与拖拽回调），`columnMetas` / `setVisible` / `setWidth` / `reset` 透传给 `ColumnSettingButton` 渲染设置面板。

### 5.8 已知行为说明

- **dev 模式接口请求成对出现**：`main.tsx` 启用了 `React.StrictMode`，开发模式下 React 会故意双挂载组件（挂载 → 卸载 → 再挂载）以暴露副作用问题，导致进入页面时各接口请求成对出现，属 React 官方预期行为，并非代码缺陷；生产构建不受影响——已实测（浏览器网络面板取证）每个模块进入时各接口均只请求 1 次，故保留 StrictMode 不做处理。
- **无 ellipsis 列的表格拖拽收窄存在下限**：rc-table 仅在列定义中存在 `ellipsis` 列时才启用 `table-layout: fixed`（当前为 ConfigurationList / VersionHistory）；无 ellipsis 列的页面为 auto 布局，列宽收窄到内容 min-content 后不再继续变窄，属浏览器表格布局的预期表现，并非拖拽调宽缺陷。

## 6. 与后端的接口约定（消费方视角）

具体端点定义、字段与错误码由后端方案负责（参见 `./后端方案.md`），前端只约定消费方式：

- **统一 `/api` 前缀**：所有请求走 `/api/*`，开发期由 Vite 代理转发，部署期同源直达；
- **统一响应结构**：后端返回统一包裹结构（业务码 + 消息 + 数据体），`http.ts` 响应拦截器负责解包——成功时直接返回数据体，失败时统一弹出 sonner toast 错误提示并 reject，页面代码不重复处理错误展示；
- **错误处理**：HTTP 非 2xx 或业务码非成功时，拦截器统一提示后端返回的 message；表单类错误由页面按需捕获做字段级展示；
- **操作人请求头**：`http.ts` 请求拦截器为所有非 GET 请求统一注入 `X-Operator` 头，取值 localStorage 的 `operator`（顶栏操作人输入框维护），缺省 `portal`（后端未收到该头时缺省记为 system）；页面代码不单独设置该头；
- **长轮询的前端使用方式**：长轮询接口是为应用客户端 SDK 设计的（携带本地 md5、服务端挂起至变更或超时）；Portal 页面**不使用**长轮询接口，编辑页的变更探测用 `usePolling` 短间隔轮询普通查询接口即可，避免占用服务端挂起连接。

## 7. 开发调试方式

- 后端 `dotnet run` 与前端 `npm run dev` 并行启动（双进程开发模式）；
- `vite.config.ts` 代理配置示例：

```ts
// vite.config.ts
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
  server: {
    proxy: {
      // /api 前缀请求代理到后端，浏览器侧同源，无跨域问题
      '/api': {
        target: 'http://localhost:5096', // 后端 dotnet run 监听地址（launchSettings.json 的 http profile）
        changeOrigin: true,
      },
    },
  },
  build: {
    outDir: '../k_config_center/wwwroot', // 构建产物输出到后端静态目录
    emptyOutDir: true,
  },
});
```

- 构建产物输出到后端 `wwwroot/` 由后端托管，单一应用部署，详见 `./项目整体架构设计.md`。
