# 前端方案（配置中心管理界面 Portal）

> 定位：纯前端视角的技术方案。
> 配套文档：`./项目整体架构设计.md`（顶层架构与部署）| `./后端方案.md`（接口定义与后端实现）| `../设计文档/配置中心设计文档.md`（领域模型）

---

## 1. 背景与页面诉求

配置中心的数据层级模型（命名空间 → 环境 → 配置组 → 配置项 → 版本快照）与发布/回滚机制已在设计文档中定稿。为了让配置的日常维护脱离直接操作数据库或裸调 API，需要为配置中心增加**管理界面（Portal）**能力。

Portal 页面清单：

| 页面 | 诉求 |
|------|------|
| 命名空间管理 | 命名空间的增删改查与启用/禁用 |
| 环境管理 | 命名空间下环境（dev/test/staging/prod）的增删改查、排序与启用/禁用 |
| 配置组管理 | 环境下配置组的增删改查与启用/禁用 |
| 配置列表与编辑 | 配置项列表（状态、未发布变更标记）；多格式内容（text / json / yaml / properties / xml / toml）编辑，具备语法高亮与基础校验 |
| 版本历史与 Diff | 查看配置项全部历史版本快照，任意两个版本（或当前编辑态与已发布版本）之间的差异对比 |
| 发布 / 回滚 | 将草稿内容发布为新版本，或以历史版本内容生成新版本回滚，配合「有未发布变更」标记 |
| 操作审计 | 按命名空间 / 环境 / 配置项等维度检索操作日志 |

## 2. 候选方案对比与选型结论

| 方案 | 技术组合 | 优点 | 缺点 | 适用场景 |
|------|----------|------|------|----------|
| 方案一 | 前后端分离 SPA：Vue 3 + Element Plus | 生态成熟、中文资料丰富、组件覆盖全面；模板语法上手门槛低 | 需要引入 Node 工具链；中后台高阶封装（如 ProTable 一类）不如 React 生态完整 | 团队以 Vue 技术栈为主、追求快速上手的中后台项目 |
| 方案二 | 前后端分离 SPA：React 18 + Ant Design 5 | 生态同样成熟；AntD ProComponents（ProTable/ProForm）对 CRUD 类中后台页面提效明显；TypeScript 支持一流；Monaco、Diff 等编辑器周边组件最丰富 | 需要引入 Node 工具链；JSX 心智模型对纯后端团队略有门槛 | 中后台管理系统的主流选择，页面以表格 + 表单 + 编辑器为主的场景 |
| 方案三 | Blazor（Server 模式 + MudBlazor） | 纯 C# 技术栈，.NET 团队零前端成本上手最快；与后端共用模型类型 | 组件生态明显弱于 Vue/React；富文本/代码编辑器等复杂组件多依赖 JS 互操作；Server 模式依赖常连接，弱网体验差 | 全员 .NET、界面复杂度中低、不想维护双技术栈的团队 |
| 方案四 | Razor Pages + htmx 轻量方案 | 架构最简单，无独立前端工程，部署零额外成本 | 富交互页面（代码编辑器、版本 Diff、多面板联动）实现吃力，可维护性随交互复杂度快速恶化 | 页面以静态展示 + 简单表单为主的小型工具站 |

**结论：选定方案二 —— React 18 + TypeScript + Ant Design 5。**

理由：配置中心 Portal 的核心页面高度依赖「表格 + 表单 + 代码编辑器 + Diff 视图」，React 生态在这几类组件上的成熟度与可组合性最好（@monaco-editor/react、react-diff-viewer-continued 均为开箱即用）；ProComponents 可显著压缩命名空间/环境/配置组等 CRUD 页面的开发量。

## 3. 技术栈清单

| 类别 | 选型 | 说明 |
|------|------|------|
| 构建工具 | Vite | 开发启动快、配置简单，内置 dev 代理能力 |
| 语言 | TypeScript | 与后端 Response/Request 模型对齐，减少接口联调错误 |
| UI 组件库 | Ant Design 5 | 中后台组件覆盖全面 |
| 路由 | react-router-dom v6 | 声明式路由，配合布局组件实现侧边栏导航 |
| 状态管理 | Zustand | 轻量全局状态方案（预留）；页面级筛选改版后不再有全局命名空间/环境上下文，当前无全局共享状态诉求，筛选条件由各页面自持 |
| HTTP 客户端 | Axios（可选 TanStack Query） | Axios 拦截器统一处理错误提示与响应解包；数据缓存/重试等诉求增强时可引入 TanStack Query |
| 代码编辑器 | @monaco-editor/react | VS Code 同源内核，原生支持 json/yaml/xml 等语法高亮 |
| 版本对比 | react-diff-viewer-continued | 双栏/单栏 Diff 视图，用于版本历史对比 |
| YAML 解析 | js-yaml | yaml 内容校验（load）与格式化（dump），供格式化器注册表使用 |
| XML 格式化 | xml-formatter | xml 内容美化（校验用浏览器原生 DOMParser，不额外引库） |
| 中后台增效（可选） | AntD ProComponents | ProTable / ProForm 提效命名空间、环境、配置组等 CRUD 页面 |

## 4. web/ 工程目录树

`web/` 是仓库根下的独立前端工程（仓库整体布局参见 `./项目整体架构设计.md`）：

```
web/
├── package.json                          # 依赖与脚本（dev / build / preview，build 前先 tsc --noEmit 类型检查）
├── vite.config.ts                        # dev 代理：/api → 后端；build.outDir → ../k_config_center/wwwroot
└── src/
    ├── main.tsx                          # 应用入口：挂载根组件 + AntD 全局配置（ConfigProvider：中文文案 + 全局主题，见 5.4）
    ├── App.tsx                           # 根组件：路由容器
    ├── api/                              # 接口层：按资源拆分，统一从 http.ts 出口
    │   ├── http.ts                       # Axios 实例与拦截器：统一错误提示、响应解包
    │   ├── namespace.ts                  # 命名空间接口
    │   ├── environment.ts                # 环境接口
    │   ├── group.ts                      # 配置组接口
    │   ├── configuration.ts              # 配置项接口：编辑/发布/回滚/版本历史
    │   └── types.ts                      # 与后端 Requests/Responses 对齐的 TypeScript 类型
    ├── router/
    │   └── index.tsx                     # 路由表：布局嵌套 + 各页面路由
    ├── layouts/
    │   └── MainLayout.tsx                # 主布局：AntD Layout 侧边栏导航 + 顶栏（当前页面标题 + 操作人输入框）
    ├── pages/                            # 页面（按资源分目录）
    │   ├── namespace/
    │   │   └── NamespaceList.tsx         # 命名空间列表与增删改
    │   ├── environment/
    │   │   └── EnvironmentList.tsx       # 环境列表与增删改
    │   ├── group/
    │   │   └── GroupList.tsx             # 配置组列表与增删改
    │   ├── configuration/
    │   │   ├── ConfigurationList.tsx     # 配置项列表：状态/未发布变更标记、发布/下线入口
    │   │   ├── ConfigurationDetailDrawer.tsx # 配置详情抽屉：只读展示列表行数据（见 5.6）
    │   │   ├── ConfigurationEditor.tsx   # 配置编辑：Monaco 编辑器 + 格式切换 + 保存/发布
    │   │   └── VersionHistory.tsx        # 版本历史：版本列表 + Diff 对比 + 回滚入口
    │   └── audit/
    │       └── OperationLogList.tsx      # 操作审计：多维度检索操作日志
    ├── components/                       # 通用业务组件
    │   ├── PageContainer.tsx             # 页面容器：统一标题区（可选 icon banner 形态）+ 白底卡片内容区（见 5.4）
    │   ├── FormDrawer.tsx                # 通用表单抽屉：新建/编辑统一入口，脏表单关闭二次确认（见 5.4）
    │   ├── ContentPreview.tsx            # 配置内容预览：单行截断 + Popover 格式化预览 + 复制全部（见 5.4）
    │   ├── CopyableText.tsx              # 可复制文本：省略展示 + 尾随复制按钮（见 5.4）
    │   ├── DimensionCell.tsx             # 维度单元格：名称 Tag + 次行 key code 框（点击复制），各维度列/信息栏统一形态（见 5.4）
    │   ├── FormatSelect.tsx              # 配置格式选择器（text/json/yaml/properties/xml/toml）
    │   ├── FormatTag.tsx                 # 配置格式标签（六格式着色映射，见 5.4 色彩体系）
    │   ├── StatusTag.tsx                 # 状态标签（DRAFT/PUBLISHED/OFFLINE 着色，无边框 Tag + 状态圆点）
    │   ├── ColumnSettingButton.tsx       # 列配置按钮（Popover 面板控制列显隐/宽度，配合 useColumnSettings，见 5.7）

        ├── clipboard.ts                  # 剪贴板复制工具（见 5.4）
        └── formatters.ts                 # 配置内容格式化器注册表（六格式校验/美化，见 5.4）
```

各目录职责：

- **api/**：所有请求经由 `http.ts` 的 Axios 实例，拦截器统一弹出错误提示并解包响应体，页面代码只关心业务数据；`types.ts` 与后端接口模型保持字段一致（模型定义参见 `./后端方案.md`），如 `ConfigurationResponse` / `EnvironmentResponse` / `ConfigurationGroupResponse` / `OperationLogResponse` 同步后端联表冗余的维度名称 / 业务 key 可选可空字段（维度列「名称 + key」展示用，见 `./后端方案.md` 7.2）；
- **router/**：集中式路由表，主布局作为父路由，各页面作为子路由嵌套渲染；
- **layouts/**：全局唯一的主布局（侧边栏 + 顶栏 + 内容区），页面组件不关心导航结构；
- **pages/ 按资源分目录**：与后端接口资源一一对应，便于前后端对照维护；筛选条件（命名空间/环境等）为页面级状态，由各页面自持，无跨页面共享上下文；
- **components/**：跨页面复用的业务组件（页面容器、表单抽屉、内容预览、可复制文本、维度单元格、格式选择、格式标签、状态标签、列配置按钮、可拖拽表头、Diff 视图）；
- **hooks/**：与 UI 无关的通用逻辑封装（表格请求、列配置持久化、轮询）；
- **utils/**：无 React 依赖的纯工具函数（剪贴板复制、配置内容格式化器注册表）。

## 5. 页面与路由设计

### 5.1 路由规划

| 路由路径 | 页面 | 说明 |
|----------|------|------|
| `/` | 重定向 | 重定向到 `/configuration` |
| `/namespace` | NamespaceList | 命名空间管理 |
| `/environment` | EnvironmentList | 环境管理（页面内按命名空间可选筛选） |
| `/group` | GroupList | 配置组管理（页面内按命名空间/环境可选筛选） |
| `/configuration` | ConfigurationList | 配置项列表（页面内五维可选组合筛选） |
| `/configuration/:id/edit` | ConfigurationEditor | 配置编辑（Monaco） |
| `/configuration/:id/versions` | VersionHistory | 版本历史与 Diff、回滚 |
| `/audit` | OperationLogList | 操作审计 |

所有页面路由挂在 `MainLayout` 布局路由之下；浏览器直接访问深层路由时由后端兜底返回 index.html（参见 `./项目整体架构设计.md` 部署机制）。

### 5.2 布局与页面级筛选

- **MainLayout**：AntD `Layout` 实现，左侧为侧边栏导航（命名空间 / 环境 / 配置组 / 配置 / 审计），顶栏 = **当前页面标题（左）+ 操作人输入框（右）**，不再放置任何全局筛选控件；
- **页面级筛选取代全局上下文**：原「顶栏命名空间/环境选择器 + useScopeStore 全局上下文 + ScopeEmpty 空态」方案已下线——命名空间/环境等过滤条件下沉为各页面独立的筛选区状态（规范见 5.5），**无筛选条件即查询全部**，页面进入即可用，无「先选上下文」前置步骤，也不再需要空态引导组件；
- **操作人来源**：顶栏操作人输入框的值持久化到 localStorage（key: `operator`），缺省 `portal`；写操作的请求头注入方式见第 6 章。

### 5.3 各页面功能点

- **NamespaceList**：表格展示名称 / namespace_key / 描述 / 状态（名称列前置于 Key 列，见 5.6）；关键字筛选；新建与编辑走 FormDrawer；启用/禁用切换；
- **EnvironmentList**：环境列表（命名空间筛选可选，不选即全部），含 sort_order 排序；「所属命名空间」列用 DimensionCell 展示名称 Tag + 业务 key（名称与 key 由后端联表冗余返回，见 5.4 色彩体系）；增删改走 FormDrawer；
- **GroupList**：配置组列表（命名空间/环境筛选均可选）；命名空间/环境列用 DimensionCell 展示名称 Tag + 业务 key（名称与 key 由后端联表冗余返回）；增删改走 FormDrawer；点击组可跳转到该组的配置列表；
- **ConfigurationList**：**五维可选组合筛选**（命名空间/环境/配置组三级级联 + 状态 + Key 关键字，全不选即全量）的配置项表格，展示命名空间 / 环境 / 所属配置组（三列 DimensionCell：名称 Tag + 次行 key code 框，key 缺失时兜底显 #id，名称与 key 均由后端联表冗余返回）/ key / 内容（当前编辑态 content，ContentPreview 单行截断 + 悬浮预览）/ 格式（FormatTag 着色）/ 状态（StatusTag 着色）/ 最新版本号 / 「有未发布变更」标记（由服务端算好返回），配置组名称列前置于 Key 列（见 5.6）；新建配置抽屉的「配置值」字段在 `canFormat` 格式下提供「校验并格式化」入口（注册表 `validate` 失败提示具体错误，通过则美化回写，见 5.4 工具函数）；行操作：详情（只读抽屉，见 5.6）、编辑、发布、版本历史，下线/删除收纳进「更多」菜单；
- **ConfigurationEditor**：Monaco 编辑器按 format 切换语言高亮；保存（写草稿并重算 md5）与发布（弹窗填变更备注）两个动作分离；保存前的前端校验统一走格式化器注册表的 `validate`（json 完整语法校验、yaml 用 js-yaml 解析校验、xml 用 DOMParser、properties/toml 行级校验、text 恒合法，详见 5.4 工具函数；另 json 格式空内容单独拦截）；可用 `usePolling` 探测他人发布导致的内容变更并提示刷新；
- **VersionHistory**：版本列表（版本号、变更类型、备注、操作人、时间）；任选两个版本 Diff，或「当前编辑态 vs 已发布版本」Diff；每个历史版本提供「回滚到此版本」入口，二次确认后调用回滚接口；
- **OperationLogList**：按命名空间 / 环境 / 配置组 / 配置项 / 操作类型 / 时间范围组合检索操作日志，detail 字段展开查看变更详情；命名空间 / 环境 / 配置组 / 配置项四个维度列用 DimensionCell 展示关联资源的名称 + key（配置项无显示名称只显 key 行；名称与 key 由后端联查冗余返回，已软删除资源也能回显，见 `./后端方案.md` 7.2；日志未关联该维度时显「-」）。

删除交互统一约定：各列表页（命名空间 / 环境 / 配置组 / 配置项）的删除操作均为软删除，由后端保证（参见 `./后端方案.md` 8.4）；界面需二次确认（AntD Popconfirm / Modal.confirm）后再调用删除接口。

其余交互统一约定（UI 现代化改版后固化）：

- **操作列收纳**：行操作列只直接展示高频操作（控制在 4 个以内，如 ConfigurationList 直接展示详情/编辑/发布/版本历史），低频/危险操作收纳进 `Dropdown`「更多」菜单（如 ConfigurationList 行操作中的下线/删除）；
- **危险操作**：统一 `danger` 样式 + 二次确认——按钮场景用 `Popconfirm`，Dropdown 菜单项场景用 `Modal.confirm`；
- **表格与表单容器**：`Table` 统一 `size="middle"`，所有列表 Table 统一 `scroll={{ x: 'max-content' }}`——窄窗口下出现横向滚动条而非内容越界溢出容器；新建/编辑统一 FormDrawer（`width={480}`），确认类 `Modal` 保留（如发布填备注、Dropdown 危险操作二次确认，`width={520}`、`maskClosable={false}`）；
- **编辑器页布局**：「顶部工具条 Card（返回 + 配置 key + 未发布变更标记 + 格式切换/操作按钮组）+ 左侧 Descriptions 配置信息卡（固定宽 320，字段口径对齐配置详情抽屉：配置 ID / 状态 / 命名空间 / 环境 / 所属配置组（DimensionCell）/ 配置项 Key（CopyableText）/ 保存格式（FormatTag，为服务端已保存格式，与工具条上本地编辑格式在未保存时可能不同）/ 当前 md5 / 生效版本 / 生效 md5 / 最新版本 / 发布时间 / 创建人 / 创建时间 / 最后修改人 / 更新时间 / 标签 / 配置说明）+ 右侧 Monaco 编辑器 Card（flex 自适应）」三段式布局；「格式化」按钮由注册表 `canFormat` 驱动展示（json/yaml/xml/properties 可格式化，toml/text 隐藏入口），先 `validate` 后 `format`，校验失败提示具体错误且不改动内容，纯前端处理不发请求；
- **版本历史**：生效版本在版本号列前置「生效中」绿色圆点 Tag 标识；「对比所选两个版本」按钮在未勾选满两个版本时禁用，并用 `Tooltip` 说明原因（`span` 包裹以保证 disabled 按钮上仍可触发提示），已勾选满两个版本后禁用其余行的勾选。

### 5.4 主题与视觉规范

UI 现代化改版后固化的主题与视觉决策：

**全局主题**：内联定义于 `main.tsx` 的 `ConfigProvider theme`，不单独拆主题文件：

| Token | 取值 | 说明 |
|-------|------|------|
| `colorPrimary` | `#2f54eb` | 品牌蓝主色 |
| `borderRadius` | `6` | 全局圆角 |
| `colorBgLayout` | `#f5f7fa` | 内容区浅灰画布底色 |
| `fontFamily` | 系统字体栈 | `-apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, 'PingFang SC', 'Microsoft YaHei', sans-serif` |

约定**不设置 `colorBgContainer`**：该 token 会同时影响输入框、卡片等所有容器底色，改动它会污染表单控件与卡片视觉；画布灰底只通过 `colorBgLayout` 实现。

**布局约定**（MainLayout）：

- 亮色 Sider（宽 200，右侧 1px 分隔线）：顶部品牌 Logo 区（CloudServerOutlined 品牌蓝图标 + 「配置中心」标题），下方图标导航菜单；

**公共组件**：

- **PageContainer** `{ title, description?, icon?, accentColor?, extra?, children }`：统一页面标题区 + 无边框 Card 内容容器，纯布局组件零业务逻辑；除配置编辑页采用专属三段式布局外，其余 6 个页面全部接入。标题区按是否传入 `icon` 分两种形态：
  - **banner 形态**（传入 `icon` 时）：标题区升级为浅色渐变 banner（渐变起点由 `accentColor` 叠透明度衍生浅色，缺省 `#f0f5ff`，到 `#ffffff`，圆角 8），内部为「40px 圆形主题色（`accentColor`，缺省品牌蓝 #2f54eb）底白色图标 + 标题 + description 副标题（次要色）+ 右侧 extra 操作区」；各页现状：命名空间（AppstoreOutlined）/ 环境（DeploymentUnitOutlined）/ 配置组（FolderOpenOutlined）/ 配置管理（SettingOutlined）/ 操作审计（AuditOutlined）五个列表页均传 icon + description，`accentColor` 取值见下文色彩体系；
  - **原布局**（不传 `icon` 时）：标题 + 可选说明 + 右侧操作区，无 banner 背景；版本历史页（仅标题）保持此形态；
- **FormDrawer** `{ title, open, onClose, onSubmit, loading?, form, width? = 480, okText? = '确定', children }`：通用表单抽屉，右侧滑出，footer 固定为「取消 + 主按钮（loading）」；防误触约定——`maskClosable={false}`、`destroyOnClose`（每次打开表单为全新实例），X / 取消统一走内部关闭逻辑：表单已被修改（`form.isFieldsTouched()`）时 `Modal.confirm` 二次确认再关闭，未修改直接关闭；
- **ContentPreview** `{ content, format }`：配置内容预览——列表单元格内单行截断（`Typography.Text ellipsis`，等宽字体），hover 弹出 Popover 展示格式化后的完整内容：按格式化器注册表 `format` 美化（失败自动回退原文，见下文工具函数）；空内容展示占位符「-」；超 5000 字符仅预览前 5000 字符并附「进编辑器查看完整内容」截断提示，避免 Popover 渲染卡顿；Popover 底部右侧提供「复制全部」按钮，复制的是**格式化后的完整原文**（不受 5000 字符展示截断影响），结果由 message 反馈；
- **CopyableText** `{ value, code?, maxWidth? }`：可复制文本——省略展示（`Typography.Text ellipsis`，Tooltip 显示全文，`code` 控制代码样式，`maxWidth` 限宽）+ 尾随复制小按钮（图标独立于文本截断之外，复制结果由 message 反馈）；使用位置：四个列表页的 Key 列（见 5.6）、配置详情抽屉与编辑器页信息栏的配置项 Key 字段；
- **StatusTag**：无边框 Tag + 状态圆点——草稿金（gold，圆点 #faad14）/ 已发布绿（green，圆点 #52c41a）/ 已下线火山橙（volcano，圆点 #fa541c），未知状态原样展示兜底；
- **FormatTag** `{ format }`：配置格式标签——无边框 Tag 按格式着色（映射见下文色彩体系），未知格式 default 兜底；
- **ColumnSettingButton** `{ columnMetas, setVisible, setWidth, reset }`：列配置按钮——设置图标 + Popover 面板（逐列 Checkbox 显隐 + InputNumber 宽度覆盖 + 「恢复默认」），Props 直接接收 `useColumnSettings` 的返回值与其配套使用（见 5.7）；
- **ResizableHeaderCell** `{ width?, onColumnResize?, onColumnResizeEnd? }`：可拖拽调宽的表头单元格——经 Table `components={{ header: { cell } }}` 替换默认表头单元格，宽度与拖拽回调由 `useColumnSettings` 通过 `onHeaderCell` 注入；未注入回调（如操作列）时退化为普通 th（机制详见 5.7）。

**工具函数**：

- **copyToClipboard** `(text: string) => Promise<boolean>`（`utils/clipboard.ts`）：剪贴板复制统一入口——优先 `navigator.clipboard.writeText`（需安全上下文），不可用或失败时降级 `document.execCommand('copy')`（临时 textarea，fixed + 透明不扰动布局，用完即移除）；返回是否复制成功，**工具内不弹提示**，由调用方（CopyableText / ContentPreview / 配置详情抽屉）根据结果用 message 反馈；
- **getFormatter** `(format: string) => ContentFormatter`（`utils/formatters.ts`）：配置内容格式化器注册表——六格式（text/json/yaml/properties/xml/toml，与后端 format 字段取值一致）各注册 `{ canFormat, validate, format }`：`validate` 返回 null 表示合法、否则返回错误描述；`format` 失败一律回退原文；`canFormat=false` 时 UI 隐藏格式化入口。各格式行为：json（`JSON.parse` 校验 + 2 空格缩进美化）/ yaml（js-yaml `load` 校验，错误信息自带行号，`dump` 美化；空内容格式化保持原样返回，不输出 null）/ xml（DOMParser 校验 + xml-formatter 2 空格缩进美化）/ properties（行级校验：空行与 `#`/`!` 注释跳过，其余须含 `=` 或 `:`，支持行尾 `\` 续行——续行中的行不要求含 `=`/`:`；美化仅去行尾空白与首尾空行，不破坏续行反斜杠）/ toml（仅行级校验：允许 `[section]`/`[[array]]` 与含 `=` 的键值行，`canFormat=false` 不支持美化）/ text（不校验不格式化：恒合法、原样返回）；未注册格式返回 text 同款兜底器。消费方：ContentPreview / 配置详情抽屉（format）、新建配置抽屉「校验并格式化」与编辑器「格式化」按钮（canFormat + validate + format）、编辑器保存前校验（validate）。

### 5.5 筛选区规范

页面级筛选改版后固化的筛选区约定（各列表页统一遵循）：

- **位置与形态**：筛选区位于 PageContainer 内容区顶部，一行 `Space wrap`（`marginBottom: 16`）排布筛选控件，无独立筛选 Card；
- **筛选行为**：`Select` 类筛选（命名空间/环境/配置组/状态）变化即触发列表重载；关键字用 `Input.Search` 提交式查询（回车/点搜索生效，非输入即查，清空输入即还原全量）；所有筛选控件均 `allowClear`，清空即查询全部——**无筛选条件即查询全部**，不存在必选前置条件；
- **级联约定**：存在层级关系的筛选（如 ConfigurationList 的命名空间 → 环境 → 配置组）上级变化时清空下级选中值，下级选项数据源按上级过滤（上级未选则全量）；
- **下拉实时刷新**：所有维度下拉（命名空间/环境/配置组，含筛选区与表单内）通过 `onDropdownVisibleChange` 在展开时按当前级联参数重新请求选项数据，保证其他页面新增后选项不陈旧；不加防抖与缓存；
- **分页**：列表统一前端分页，`pageSize: 10` + `showSizeChanger` + `showTotal`（「共 N 条」）；
- **表单入口**：新建/编辑统一走 FormDrawer；发布（填变更备注）等确认类弹窗保留 `Modal`。

### 5.6 名称前置与配置详情抽屉规范

「名称前置与视觉精修」改版后固化的列序与详情展示约定：

**名称前置于 Key**（四个列表页统一）：

- **列顺序**：名称类列统一排在 Key 列之前——NamespaceList / EnvironmentList / GroupList 均为「名称 → Key」；ConfigurationList 为「所属配置组（名称 Tag）→ 配置项 Key」；意图是人读名称优先，机读标识退居其后；
- **Key 列展示**：四个列表页的 Key 列统一用 `CopyableText` 的 `code` 样式渲染（等宽代码观感 + 一键复制）；
- **表单字段顺序**：与列序一致，名称类字段排在 Key 字段之前——命名空间/环境/配置组表单均为「名称 → Key → 其余字段」，新建配置表单为「配置组 → 配置项 Key → 格式/配置值/说明」。

**配置详情抽屉**（ConfigurationDetailDrawer `{ open, record, onClose, onEdit }`）：

- **数据来源**：直接复用列表行数据（`ConfigurationResponse`，命名空间/环境/配置组名称与业务 key 由后端联表冗余返回，见 `./后端方案.md` 7.2），打开抽屉**零额外请求**；
- **只读定位**：无表单无脏检测，用普通 `Drawer`（`width={560}`、`destroyOnClose`）而非 FormDrawer；Descriptions（双列带边框）展示配置 ID / 状态（StatusTag）/ 命名空间 / 环境 / 所属配置组（三者均为 DimensionCell：名称 Tag + 次行 key code 框，key 缺失时兜底显 #id，见 5.4 色彩体系）/ 配置项 Key（CopyableText code）/ 格式 / 最新版本 / 最后修改人 / 创建时间 / 更新时间 / 配置说明；
- **配置值区块**：格式化后（注册表 `format`，失败回退原文）的只读代码块（灰底 `pre`，等宽字体，限高滚动），超 5000 字符截断展示并提示进编辑器查看；「复制全部」复制格式化后的完整内容，不受展示截断影响；
- **编辑入口**：抽屉右上角「编辑配置」主按钮，通过 `onEdit` 交回列表页关闭抽屉并跳转编辑器页（`/configuration/:id/edit`），抽屉内不提供任何写操作。

### 5.7 列配置持久化约定

列表升级改版后，六个列表页统一接入「列显隐 + 宽度覆盖」配置能力（`useColumnSettings` hook + 筛选区右侧的 `ColumnSettingButton`，宽度另支持表头拖拽调整）：

- **localStorage key 规范**：`column-settings:${pageKey}`，各页 pageKey 固定为：namespace-list / environment-list / group-list / operation-log-list / configuration-list / version-history（版本历史页于拖拽调宽轮新接入列配置）；
- **操作列强制显示**：key 为 `'action'` 的操作列不参与配置——始终展示，不出现在设置面板的可配置清单中，也不参与拖拽调宽（不注入拖拽回调，表头退化为普通单元格）；
- **列宽拖拽调整**：非操作列表头右缘渲染 8px 拖拽手柄（`ResizableHeaderCell`），基于指针事件 + 指针捕获实现（`setPointerCapture` 保证移出手柄后 move/up 事件不丢失），零第三方依赖；最小宽度 60（`MIN_COLUMN_WIDTH`，与设置面板 InputNumber 的 min 对齐）；拖动过程中仅更新内存态做实时反馈，松手才写入 localStorage（避免高频写盘）；拖拽与设置面板 InputNumber 共用同一份宽度配置，任一侧修改另一侧即时同步；
- **列 key 取值**：优先列定义的显式 `key`，无 key 用 `dataIndex` 兜底（数组型以 `.` 连接），再兜底索引占位；
- **容错**：读取时 JSON 解析失败视为无配置；写入失败（localStorage 不可用）静默降级为仅内存态；宽度覆盖仅接受不低于下限的有限数值，存储被改坏（负数/NaN）时按无覆盖处理；「恢复默认」清空内存态并移除存储项；
- **接入方式**：页面把列定义交给 `useColumnSettings(pageKey, columns)`，返回的 `mergedColumns` 与 `components` 直接交给 Table（`components` 把表头单元格替换为 `ResizableHeaderCell`，宽度与拖拽回调经各列 `onHeaderCell` 注入），`columnMetas` / `setVisible` / `setWidth` / `reset` 透传给 `ColumnSettingButton` 渲染设置面板。

### 5.8 已知行为说明

- **dev 模式接口请求成对出现**：`main.tsx` 启用了 `React.StrictMode`，开发模式下 React 会故意双挂载组件（挂载 → 卸载 → 再挂载）以暴露副作用问题，导致进入页面时各接口请求成对出现，属 React 官方预期行为，并非代码缺陷；生产构建不受影响——已实测（浏览器网络面板取证）每个模块进入时各接口均只请求 1 次，故保留 StrictMode 不做处理。
- **无 ellipsis 列的表格拖拽收窄存在下限**：rc-table 仅在列定义中存在 `ellipsis` 列时才启用 `table-layout: fixed`（当前为 ConfigurationList / VersionHistory）；无 ellipsis 列的页面为 auto 布局，列宽收窄到内容 min-content 后不再继续变窄，属浏览器表格布局的预期表现，并非拖拽调宽缺陷。

## 6. 与后端的接口约定（消费方视角）

具体端点定义、字段与错误码由后端方案负责（参见 `./后端方案.md`），前端只约定消费方式：

- **统一 `/api` 前缀**：所有请求走 `/api/*`，开发期由 Vite 代理转发，部署期同源直达；
- **统一响应结构**：后端返回统一包裹结构（业务码 + 消息 + 数据体），`http.ts` 响应拦截器负责解包——成功时直接返回数据体，失败时统一弹出 AntD message 错误提示并 reject，页面代码不重复处理错误展示；
- **错误处理**：HTTP 非 2xx 或业务码非成功时，拦截器统一提示后端返回的 message；表单类错误由页面按需捕获做字段级展示；
- **操作人请求头**：`http.ts` 请求拦截器为所有非 GET 请求统一注入 `X-Operator` 头，取值 localStorage 的 `operator`（顶栏操作人输入框维护），缺省 `portal`（后端未收到该头时缺省记为 system）；页面代码不单独设置该头；
- **长轮询的前端使用方式**：长轮询接口是为应用客户端 SDK 设计的（携带本地 md5、服务端挂起至变更或超时）；Portal 页面**不使用**长轮询接口，编辑页的变更探测用 `usePolling` 短间隔轮询普通查询接口即可，避免占用服务端挂起连接。
