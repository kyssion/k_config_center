# 配置中心设计文档（Config Center Design）

> 项目：k_config_center

> 配套 DDL 脚本：`../数据库脚本/配置中心建表脚本.sql`
> 实现方案：`../技术方案/项目整体架构设计.md` | `../技术方案/后端方案.md` | `../技术方案/前端方案.md`

## 1. 概述与层级模型

配置中心用于集中管理应用配置，支持多命名空间、多环境隔离，配置具备**版本快照、发布/回滚、状态机、软删除**能力。层级模型为：

```
namespace（命名空间，业务线/团队级隔离，默认 public）
└── environment（环境：dev / test / staging / prod）
    └── configuration_group（配置组：一组相关配置的集合，如某个微服务）
        └── configuration（配置项：key + content，带格式、版本、状态）
            └── configuration_version（历史版本快照，不可变，线性递增）
```

ASCII 结构示例：

```
public (namespace)
├── dev (environment)
│   ├── order-service (group)
│   │   ├── appsettings          [json]   PUBLISHED  v5
│   │   └── redis.connection     [text]   PUBLISHED  v2
│   └── user-service (group)
│       └── logging              [yaml]   DRAFT      v0
└── prod (environment)
    └── order-service (group)
        └── appsettings          [json]   PUBLISHED  v12
```

## 2. ER 关系说明

```
config_center_namespace 1 ──── * config_center_environment
config_center_namespace 1 ──── * config_center_configuration_group
config_center_environment       1 ──── * config_center_configuration_group
config_center_configuration_group 1 ─ * config_center_configuration
config_center_configuration    1 ──── * config_center_configuration_version
config_center_configuration    * ──── 1 config_center_configuration_version   (published_version_id，延迟外键)
config_center_operation_log ──── 仅存 ID，无外键约束
```

| 关系 | 说明 |
|------|------|
| config_center_environment.namespace_id → config_center_namespace.id | 环境隶属命名空间，`unique_environment_namespace_key` 部分唯一索引保证命名空间内环境标识唯一（未软删除范围） |
| config_center_configuration_group.environment_id → config_center_environment.id | 配置组隶属环境，`unique_group_environment_key` 部分唯一索引保证环境内组标识唯一（未软删除范围） |
| config_center_configuration.group_id → config_center_configuration_group.id | 配置项隶属配置组，`unique_configuration_key` 部分唯一索引保证组内 key 唯一（未软删除范围） |
| config_center_configuration.namespace_id / environment_id | **冗余字段**，客户端高频按 namespace+environment 读取时避免三表 JOIN |
| config_center_configuration_version.configuration_id → config_center_configuration.id | 发布历史快照，`UNIQUE(configuration_id, version_number)` 保证版本号唯一 |
| config_center_configuration.published_version_id → config_center_configuration_version.id | 指向当前生效版本；因两表互相引用，该外键在两表建成后 `ALTER TABLE` 延迟添加 |
| config_center_operation_log | 审计流水，只记录各级 ID，不建外键，避免拖累主表写入/删除 |

关键字段用途：

- `config_center_configuration.md5`：当前内容摘要，用于「有未发布变更」判断与客户端长轮询变更探测。
- `config_center_configuration.latest_version_number`：已发布的最大版本号，发布时 +1；0 表示从未发布。
- `config_center_configuration.published_version_id`：当前对外生效的版本快照 ID。
- `deleted_at`：软删除标记，NULL 表示有效；namespace / environment / configuration_group / configuration 四张主资源表均有该列（全资源统一软删除，见第 5 章）。

## 3. 表结构详细说明

> 通用说明：所有表的 `id` 均由数据库 `IDENTITY` 自增生成（`BIGINT GENERATED ALWAYS AS IDENTITY`），插入时无需也不允许显式赋值；含 `updated_at` 列的表（namespace / environment / configuration_group / configuration）由数据库 `BEFORE UPDATE` 触发器自动刷新更新时间（见 4.5 时间戳自动维护），应用层无需手动赋值。

### 3.1 config_center_namespace 命名空间表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT IDENTITY | 自增主键 |
| namespace_key | VARCHAR(128) | 命名空间业务标识，全局唯一（未软删除范围），默认 `'public'` |
| namespace_name | VARCHAR(128) | 显示名称 |
| description | VARCHAR(512) | 描述 |
| status | SMALLINT | 状态：1=启用，0=禁用，默认 1 |
| deleted_at | TIMESTAMPTZ | 软删除时间，NULL=未删除 |
| created_by / updated_by | VARCHAR(64) | 创建人 / 最后修改人 |
| created_at / updated_at | TIMESTAMPTZ | 创建 / 更新时间，默认 `now()` |

索引：部分唯一索引 `CREATE UNIQUE INDEX unique_namespace_key ON config_center_namespace (namespace_key) WHERE deleted_at IS NULL;`。

脚本末尾初始化一条 `public` 命名空间记录。

### 3.2 config_center_environment 环境表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT IDENTITY | 自增主键 |
| namespace_id | BIGINT | 外键 → config_center_namespace(id) |
| environment_key | VARCHAR(64) | 环境业务标识（dev/test/staging/prod），命名空间内唯一（未软删除范围） |
| environment_name | VARCHAR(128) | 显示名称 |
| description | VARCHAR(512) | 描述 |
| sort_order | INT | 排序值，默认 0 |
| status | SMALLINT | 状态，默认 1 |
| deleted_at | TIMESTAMPTZ | 软删除时间，NULL=未删除 |
| created_at / updated_at | TIMESTAMPTZ | 时间戳，默认 `now()` |

索引：部分唯一索引 `CREATE UNIQUE INDEX unique_environment_namespace_key ON config_center_environment (namespace_id, environment_key) WHERE deleted_at IS NULL;`。

### 3.3 config_center_configuration_group 配置组表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT IDENTITY | 自增主键 |
| namespace_id | BIGINT | 外键 → config_center_namespace(id) |
| environment_id | BIGINT | 外键 → config_center_environment(id) |
| group_key | VARCHAR(128) | 配置组业务标识（编程标识符），环境内唯一（未软删除范围） |
| group_name | VARCHAR(128) | 显示名称 |
| description | VARCHAR(512) | 描述 |
| status | SMALLINT | 状态，默认 1 |
| deleted_at | TIMESTAMPTZ | 软删除时间，NULL=未删除 |
| created_by / updated_by | VARCHAR(64) | 操作人 |
| created_at / updated_at | TIMESTAMPTZ | 时间戳 |

索引：

- 部分唯一索引：`CREATE UNIQUE INDEX unique_group_environment_key ON config_center_configuration_group (environment_id, group_key) WHERE deleted_at IS NULL;`
- 查询索引：`index_group_namespace_environment(namespace_id, environment_id)`。

### 3.4 config_center_configuration 配置表（当前态）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT IDENTITY | 自增主键 |
| group_id | BIGINT | 外键 → config_center_configuration_group(id) |
| namespace_id | BIGINT | 冗余命名空间 ID，避免 JOIN |
| environment_id | BIGINT | 冗余环境 ID，避免 JOIN |
| configuration_key | VARCHAR(256) | 配置键 |
| content | TEXT | 当前（编辑态）内容 |
| format | VARCHAR(16) | 默认 `'text'`，CHECK IN ('text','json','yaml','properties','xml','toml') |
| md5 | CHAR(32) | 当前内容 MD5 |
| description | VARCHAR(512) | 描述 |
| tags | VARCHAR(256) | 标签，逗号分隔 |
| status | VARCHAR(16) | 默认 `'DRAFT'`，CHECK IN ('DRAFT','PUBLISHED','OFFLINE') |
| published_version_id | BIGINT | 指向生效版本，外键 → config_center_configuration_version(id)（延迟建立） |
| latest_version_number | BIGINT | 最新版本号，默认 0 |
| published_at | TIMESTAMPTZ | 最近发布时间 |
| deleted_at | TIMESTAMPTZ | 软删除时间，NULL=未删除 |
| created_by / updated_by | VARCHAR(64) | 操作人 |
| created_at / updated_at | TIMESTAMPTZ | 时间戳 |

索引：

- 部分唯一索引：`CREATE UNIQUE INDEX unique_configuration_key ON config_center_configuration (group_id, configuration_key) WHERE deleted_at IS NULL;`
- 查询索引：`index_configuration_namespace_environment(namespace_id, environment_id, status)`。

### 3.5 config_center_configuration_version 配置版本表（历史快照，不可变）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT IDENTITY | 自增主键 |
| configuration_id | BIGINT | 外键 → config_center_configuration(id) |
| version_number | BIGINT | 版本号，`UNIQUE(configuration_id, version_number)` |
| content | TEXT | 该版本内容快照 |
| format | VARCHAR(16) | 该版本格式 |
| md5 | CHAR(32) | 该版本内容 MD5 |
| change_type | VARCHAR(16) | CHECK IN ('CREATE','UPDATE','DELETE','ROLLBACK','IMPORT') |
| change_remark | VARCHAR(512) | 变更备注 |
| created_by | VARCHAR(64) | 操作人 |
| created_at | TIMESTAMPTZ | 创建时间 |

索引：`index_version_configuration(configuration_id, version_number DESC)`。快照写入后不再修改；版本记录不提供删除能力（不设 deleted_at）。

### 3.6 config_center_operation_log 操作日志表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT IDENTITY | 自增主键 |
| namespace_id / environment_id / group_id / configuration_id | BIGINT | 各级 ID，**无外键约束** |
| operation | VARCHAR(32) | CREATE/UPDATE/PUBLISH/ROLLBACK/OFFLINE/DELETE |
| detail | JSONB | 操作详情（如变更前后 diff、请求参数） |
| operator | VARCHAR(64) | 操作人 |
| client_ip_address | VARCHAR(64) | 来源 IP |
| created_at | TIMESTAMPTZ | 操作时间 |

索引：`index_operation_log_configuration(configuration_id, created_at DESC)`。审计记录不提供删除能力（不设 deleted_at）。

## 4. 版本与发布机制

### 4.1 编辑（DRAFT / 未发布变更）

- 新建配置：写入 `config_center_configuration`，`status='DRAFT'`，`latest_version_number=0`，计算 `md5`。
- 修改配置：只更新 `config_center_configuration.content / md5 / format` 等当前态字段，**不产生版本记录**。
- 「有未发布变更」的判定：`config_center_configuration.md5` ≠ `published_version_id` 指向的 `config_center_configuration_version.md5`（或从未发布）。界面上可据此展示"待发布"标记。

### 4.2 发布（PUBLISH）

事务内执行：

1. `latest_version_number = latest_version_number + 1`；
2. 将当前 `content/format/md5` 写入 `config_center_configuration_version`（`version_number = 新版本号`，`change_type='CREATE'`（首发）或 `'UPDATE'`）；
3. 更新 `config_center_configuration.published_version_id = 新快照 id`，`status='PUBLISHED'`，`published_at=now()`；
4. 写 `config_center_operation_log`（operation='PUBLISH'）。

### 4.3 回滚（ROLLBACK）

回滚**不回退版本号**，而是以历史版本内容生成一个新版本，保持版本线性递增、历史可追溯：

1. 取目标历史版本 `config_center_configuration_version(version_number=N)` 的 content/format/md5；
2. `latest_version_number + 1`，写入新快照，`change_type='ROLLBACK'`，备注中记录"回滚自 vN"；
3. 更新 `config_center_configuration` 当前态内容和 `published_version_id`；
4. 写操作日志（operation='ROLLBACK'）。

### 4.4 客户端读取与变更探测

- 读取路径：按 `namespace + environment + group (+ key)` 查询，命中 `index_configuration_namespace_environment` / `unique_configuration_key`；只返回 `status='PUBLISHED' AND deleted_at IS NULL` 的记录，内容取 `published_version_id` 指向的版本快照（保证读到的是"已发布内容"而非编辑中的草稿）。
- 变更探测（长轮询）：客户端携带本地缓存的 `md5` 发起长轮询；服务端对比生效版本的 md5，不一致（或超时）立即返回，客户端再拉取最新内容。md5 对比成本低，适合高频探测。

### 4.5 时间戳自动维护

PostgreSQL 不支持 MySQL 的 `ON UPDATE CURRENT_TIMESTAMP`，建表脚本通过通用触发器函数 `function_automatic_update_updated_at()` 配合各表的 `BEFORE UPDATE FOR EACH ROW` 触发器（如 `trigger_config_center_namespace_update_updated_at`），在行更新前自动将 `updated_at` 刷新为当前时间；`created_at` 由列默认值 `now()` 在插入时生成。两者均由数据库维护，应用层不需要手动赋值。

## 5. 状态机说明

```
            publish              offline
  DRAFT ────────────► PUBLISHED ────────► OFFLINE
    ▲                     │  ▲               │
    │      edit(内容变更但  │  └── publish ────┘   （重新发布可恢复上线）
    │      状态保持已发布)  │
    └─────────────────────┘（未发布过的编辑态）

  任意状态 ──delete──► 软删除（deleted_at = now()，status 不变）
```

- **DRAFT**：新建后未发布，客户端不可见。
- **PUBLISHED**：已发布生效；再次编辑不改变状态，仅产生"未发布变更"。
- **OFFLINE**：主动下线，客户端不可见，但保留全部版本历史，可重新发布上线。
- **软删除（全资源统一策略）**：软删除不仅适用于配置项，namespace / environment / configuration_group / configuration 四类主资源的删除均为置 `deleted_at`，全系统禁止物理删除；存在未删除子资源时拒绝删除父资源（级联语义见 `../技术方案/后端方案.md` 8.4）。各表的部分唯一索引（`WHERE deleted_at IS NULL`）自动放行同 key 重建；版本与审计记录不可删除，永久保留可审计。

## 7. 设计取舍说明

1. **为何在 config_center_configuration 冗余 namespace_id / environment_id**
   客户端拉取配置是最高频路径（按 namespace+environment 批量拉取、长轮询探测），若每次都 `configuration → group → environment → namespace` 三级 JOIN，成本高且索引利用差。冗余两列后单表命中 `index_configuration_namespace_environment(namespace_id, environment_id, status)` 即可完成过滤。代价是配置组不允许跨环境迁移（或迁移时需同步冗余列），该操作极低频，可接受。

2. **为何用 VARCHAR + CHECK 而非 PostgreSQL ENUM**
   ENUM 增删值需要 `ALTER TYPE`（删除值尤其麻烦，且在事务/复制场景有限制），跨库迁移与 ORM 映射也更繁琐。`VARCHAR(16) + CHECK` 语义等价、约束同样落在数据库层，扩展新状态只需重建 CHECK 约束，ORM 侧直接映射字符串，简单可靠。

3. **部分唯一索引 + 软删除**
   若用普通唯一约束 `UNIQUE(group_id, configuration_key)`，软删除后的旧记录会永久占用 key，导致同名配置无法重建。部分唯一索引 `WHERE deleted_at IS NULL` 只约束"活着"的记录：删除后同 key 可立即重建，而历史（已删）记录仍保留用于审计与版本追溯。该做法已扩展到全部四张主资源表：`unique_namespace_key`、`unique_environment_namespace_key`、`unique_group_environment_key`、`unique_configuration_key` 均为 `WHERE deleted_at IS NULL` 的部分唯一索引，与"全资源统一软删除"策略配套。

4. **content 用 TEXT 而非 JSONB**
   配置内容格式多样（text/yaml/properties/xml/toml），并非都是 JSON；JSONB 会拒绝非法 JSON 且不保留键序和原始排版，而配置文件的注释、缩进、顺序对人类可读性很重要。TEXT 原样存储所见即所得，格式校验放在应用层按 `format` 字段执行；配置中心不需要对 content 做 JSON 路径查询，JSONB 的索引优势用不上（审计的 `detail` 才需要，故日志表用 JSONB）。

## 8. 可选扩展（仅规划，不在本期 DDL 中）

- **灰度发布表（config_center_gray_release）**：记录配置的灰度版本与灰度规则（按 IP 列表 / 客户端标签 / 百分比），客户端拉取时先匹配灰度规则命中灰度版本，否则回落正式 `published_version_id`；全量发布时将灰度版本转正并关闭灰度记录。
- **监听推送记录表（config_center_listener / config_center_push_record）**：登记各客户端实例正在监听的 namespace+environment+group 及其本地 md5，用于观测配置下发覆盖率；推送记录表记录每次变更推送到各实例的结果与耗时，便于排查"配置没生效"类问题。
- **权限表（config_center_user / config_center_role / config_center_permission）**：按 namespace（或细到 environment/group）粒度授权，区分读、写、发布、回滚权限；发布/回滚等高危操作可叠加审批流。操作日志表已有 `operator` 字段，可与用户体系打通形成完整审计链。
