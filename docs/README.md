# docs/ 文档索引与维护规则

本目录是项目的文档真源,与代码同等维护。总纲见仓库根 [AGENTS.md](../AGENTS.md)。

## 文档清单

| 文档 | 路径 | 职责 |
| ---- | ---- | ---- |
| 配置中心设计文档 | `设计文档/配置中心设计文档.md` | 领域模型、ER 关系、表结构、版本与发布机制、状态机、设计取舍 |
| 项目整体架构设计 | `技术方案/项目整体架构设计.md` | 总体架构、部署形态、工程约定、演进路线 |
| 后端方案 | `技术方案/后端方案.md` | 后端分层、SqlSugar 接入、API 端点清单、错误码、核心流程 |
| 前端方案 | `技术方案/前端方案.md` | 前端选型、工程结构、页面与路由设计、接口消费约定 |
| 建表脚本 | `数据库脚本/配置中心建表脚本.sql` | PostgreSQL DDL 唯一真源(含注释与初始化数据) |

## 文档维护规则

**改了什么,就同步更新对应文档——文档与代码不允许长期分叉:**

| 变更类型 | 必须同步的文档 |
| -------- | -------------- |
| API 端点 / 请求响应结构 / 错误码 | `技术方案/后端方案.md` |
| 页面 / 路由 / 前端工程结构 | `技术方案/前端方案.md` |
| 表结构(新增列 / 索引 / 新表) | `数据库脚本/配置中心建表脚本.sql`(先改脚本再改代码,DDL 以脚本为准) + `设计文档/配置中心设计文档.md` |
| 领域模型 / 状态机 / 发布回滚语义 | `设计文档/配置中心设计文档.md` |
| 总体架构 / 部署形态 | `技术方案/项目整体架构设计.md` |

补充约定:

1. 只改实现、不动对外契约与领域语义时,可以不改文档,但代码注释须说清"为什么"。
2. 文档描述与代码行为冲突时,**以代码为准**,并在同一次提交里修正文档。
3. 新增文档放对应子目录(`设计文档/`、`技术方案/`、`数据库脚本/`),并把条目登记进上面的清单表。
