## 2026-09-07 前端 UI 框架替换：Ant Design 5 → Tailwind CSS v4 + shadcn/ui

### 背景

前端 UI 层从 antd 整体迁移至 Tailwind + shadcn/ui。动机：shadcn 组件源码直接入库（`src/components/ui/`）可读可改、无 node_modules 黑盒；Tailwind 工具类 + 类型系统对 AI 辅助开发友好；顺带移除 antd 的全部传递依赖（dayjs、rc-* 系列）与既已确认的死依赖 zustand。

### 方案

1. **基建**：Tailwind v4 经 `@tailwindcss/vite` 插件接入（CSS-first，无 tailwind.config）；`src/index.css` 以 CSS 变量定义设计令牌（沿用品牌蓝 `#2f54eb` 主色与 `#f5f7fa` 画布底色，shadcn 约定命名）；`src/lib/utils.ts` 提供 `cn()`；动画用 tw-animate-css；
2. **shadcn 组件**（`components/ui/`）：button / input / textarea / label / select / dialog / alert-dialog / sheet / badge / card / checkbox / tooltip / popover / dropdown-menu / separator / alert / skeleton / sonner（均基于 Radix 原语，light-only）；
3. **antd 组件的等价替代**：Table → 自研 `DataTable`（列定义 + loading 遮罩 + 客户端/服务端分页 + 行选择（限选数）+ 行展开 + 表头拖拽调宽）；Form → 受控组件 + `FormField` 排版（手动校验，不引入表单库）；message → sonner toast；Popconfirm / Modal.confirm → 页面级 AlertDialog；Drawer → Sheet；Descriptions → 自绘键值对网格；RangePicker → 两个原生 `datetime-local` 输入；Select allowClear → `FilterSelect` 头部「全部」选项；@ant-design/icons → lucide-react；`useColumnSettings` 列类型从 `ColumnsType`（antd）换为 `DataTableColumn`，注入方式从 `onHeaderCell` 改为 `headerResize` 属性，拖拽调宽能力（ResizableHeaderCell）原样保留；
4. **顺手修正**：`router/index.tsx` 落实编辑页 `React.lazy` 懒加载（2026-08-17 期第八节声称但未实际接线）——Monaco 拆为编辑页专属 chunk，主包从 4.67MB 降至 644KB（gzip 209KB）；
5. **依赖**：新增 tailwindcss / @tailwindcss/vite / tw-animate-css / class-variance-authority / clsx / tailwind-merge / lucide-react / sonner / 8 个 @radix-ui 包 / monaco-editor（原为传递依赖，转直接钉版）；移除 antd / @ant-design/icons / zustand；
6. **视觉二次迭代（同日）**：脱离 antd 观感，重定为现代 shadcn 风格——主色从品牌蓝 #2f54eb 改为近黑 #18181b（zinc-950），画布 #fafafa，圆角基准 10px，全局细滚动条；侧边栏改深色（zinc-950 + 白色浮起高亮），顶栏只留分区小标题 + 右侧输入框（避免与页头双标题）；PageContainer 去渐变横幅改「图标 chip + 清爽页头」，内容不再包卡片（由 DataTable 圆角白卡承担）；表头去灰底、行距加大（py-3）、空态带收件箱图标、分页按钮 ghost 化；全部徽标改无描边软色胶囊（green→emerald、purple→violet 等现代色名）；`accentColor` 属性随之移除。

**涉及文件**：`web/src` 下 main.tsx、index.css（新增）、lib/utils.ts（新增）、components/ui/*（新增 18 个）、DataTable / FormField / FilterSelect（新增）、其余 11 个业务组件与 8 个页面全部重写、http.ts / MainLayout / router / useColumnSettings 改造；vite.config.ts、package.json。

**验证**：`tsc --noEmit && vite build` 通过（0 错误）；连开发库起前后端实测——配置管理 / 命名空间 / 操作审计 / 配置编辑器（Monaco 懒加载 + YAML 高亮）四页截图核验：布局、徽标着色、分页器、抽屉、筛选区均正常。已知行为差异：命名空间页关键字从「回车/点搜索生效」改为「输入即过滤」；删除确认文案补充「存在未删除下级资源时将被拒绝」说明。

## 2026-08-17 性能与安全优化（代码评审落地）

### 背景

对项目做了一次全面代码评审，识别出性能、安全、部署三方面共十余个优化点。本期落地了其中优先级最高的部分（评审中建议的实施顺序：① 长轮询查询瘦身 → ② 客户端接口认证与限流 → ③ Monaco 本地化与静态资源缓存），全部变更均通过构建与运行时端到端验证。

### 一、长轮询性能优化（信号驱动 + 轻量指纹）

**问题**：原 `WaitForChangeAsync` 每 2 秒重算一次组指纹，且复用的查询 `ListPublishedByBusinessKeysAsync` 在 SELECT 中携带 `v.Content` 全量配置正文——每个挂起客户端每 30 秒窗口产生 15 次五表联查并拉全组内容，N 个客户端即 N×15 次/30s 的数据库压力；变更感知延迟最高 2 秒。

**方案**：

1. 新增轻量查询 `ListPublishedKeyMd5ByBusinessKeysAsync`（`ConfigurationRepository.cs`）：同口径可见性规则，只取 key 与生效版本 md5，指纹计算不再携带正文；
2. 新增进程内事件总线 `ConfigurationChangeNotifier`（`Infrastructure/ConfigurationChangeNotifier.cs`，DI 单例）：发布 / 回滚 / 下线 / 软删除成功后按「命名空间+环境+配置组」通道唤醒全部挂起的长轮询请求，等待者立即重算指纹并返回——从轮询式变为**信号驱动**，变更感知从秒级降为即时；
3. 保留最长 10 秒一次的兜底复检（防御信号丢失），挂起上限仍为 30 秒，客户端断开经 `RequestAborted` 静默取消，协议（请求/响应结构）完全不变。

**涉及文件**：`src/Infrastructure/ConfigurationChangeNotifier.cs`（新增）、`src/Repositories/ConfigurationRepository.cs`、`src/Services/ClientConfigurationService.cs`、`src/Services/PublishService.cs`、`src/Services/ConfigurationService.cs`（软删除后唤醒）、`Program.cs`（DI 注册）。

**验证**：指纹不一致 0.08s 返回 changed=true；一致时正确挂起；挂起中发布新配置，**0.51s** 内被唤醒返回（旧实现需等最多 2s 轮询周期）。

**限制**：事件仅进程内传递，多实例部署需引入 PostgreSQL `LISTEN/NOTIFY` 广播（见后续规划）。

### 二、发布并发防重（守卫式取号）

**问题**：30002「无未发布变更」的前置校验在事务外，两个并发发布可同时通过校验，各自原子取号后写入两条内容相同的版本（历史出现冗余记录；唯一约束兜底只能防同号，防不住同内容异号）。

**方案**：新增 `TryIncrementLatestVersionNumberForPublishAsync`（`ConfigurationRepository.cs`），把「存在可发布变更」（从未发布 / OFFLINE 重新上线 / 当前 md5 不同于生效版本 md5）的判定以 `IS DISTINCT FROM` 子查询并入行锁串行化的 `UPDATE ... RETURNING` 取号语句；条件不满足返回 null，Service 层重查区分 10002（配置不存在）/ 30002（并发重复发布竞败）。原无条件取号方法保留，供回滚流程使用（回滚总是产生新版本）。事务外的友好前置校验保留，原子守卫作为竞态兜底。

**涉及文件**：`src/Repositories/ConfigurationRepository.cs`、`src/Services/PublishService.cs`。

**验证**：正常发布链路（创建→发布→生效）与无变更重复发布（返回 30002）均通过端到端测试。

### 三、客户端接口 API Key 认证（可选启用）

**问题**：`/api/client/*` 可无认证拉取全部已发布配置。

**方案**：新增 `ClientApiKeyMiddleware`（`Infrastructure/ClientApiKeyMiddleware.cs`）：配置 `ClientAuth:ApiKey` 为非空值后，`/api/client/*` 必须携带取值一致的 `X-Api-Key` 请求头。固定时间比较（`CryptographicOperations.FixedTimeEquals`）防时序侧信道；失败返回 **HTTP 401 + `{code: 10003}`**。未配置时保持开放（开发环境零配置可用），启动时输出告警日志提醒。认证失败属协议层拒绝而非业务失败，故不走「业务错误 HTTP 200」约定。

**涉及文件**：`src/Infrastructure/ClientApiKeyMiddleware.cs`（新增）、`src/Infrastructure/ErrorCodes.cs`、`Program.cs`、`appsettings.json`（新增 `ClientAuth` 节）。

**验证**：启用后无 Key 返回 401/10003，带 Key 返回 200，管理端接口不受影响。

### 四、客户端接口限流

**问题**：长轮询接口被高频调用会占满连接与数据库资源，无任何保护。

**方案**：接入框架内置 `System.Threading.RateLimiting`（无新增依赖），按 IP 分区：

- `client` 策略（固定窗口，默认每 IP 每分钟 600 次，`RateLimiting:ClientPerMinute`）：应用于两个配置拉取接口；
- `client-long-poll` 策略（并发上限，默认每 IP 200 个挂起请求，`RateLimiting:LongPollConcurrency`）：应用于 `/api/client/notifications`，挂起期间占额度，防止连接耗尽。

触发限流返回 **HTTP 429 + `{code: 10004}`**。阈值可经 `appsettings.json` / 环境变量调整。

**涉及文件**：`Program.cs`、`src/Controllers/ClientConfigurationController.cs`（`[EnableRateLimiting]` 注解）、`src/Infrastructure/ErrorCodes.cs`、`appsettings.json`（新增 `RateLimiting` 节）。

**验证**：连续请求在窗口边界（第 600 次）精确触发 429/10004。

### 五、静态资源缓存策略与 SPA 兜底缓存头

**问题**：裸 `UseStaticFiles()` 无缓存头，1.4MB 主 JS 无法被浏览器长缓存；且根路径 `/` 与 SPA 深链走 `MapFallbackToFile`，不经过 `StaticFileOptions.OnPrepareResponse`，缓存头无附着点。

**方案**：

- `/assets/*`（Vite 产物文件名带内容哈希）返回 `Cache-Control: public, max-age=31536000, immutable`；
- `index.html`（含 `MapFallbackToFile` 路径）改为自定义 `MapFallback` + `SendFileAsync` 显式返回 `Cache-Control: no-cache`，保证发版后客户端立即感知新版本资源引用。

**涉及文件**：`Program.cs`。

**验证**：`/assets/*.js` 返回 immutable；`/` 与 `/configuration/9/edit` 深链均返回 `no-cache`。

### 六、响应压缩

**方案**：接入 `Brotli`/`Gzip` 响应压缩中间件，MIME 列表补充 `application/json`，API JSON 与静态资源出口均压缩。

**涉及文件**：`Program.cs`。

**验证**：assets 返回 `Content-Encoding: br` + `Vary: Accept-Encoding`；API JSON gzip 后 335B（原 535B）。

### 七、连接串占位符 fail-fast

**问题**：生产 `appsettings.json` 内置 `CHANGE_ME` 占位符，漏配环境变量时启动不报错，拖到首次查库才失败。

**方案**：`SqlSugarSetup` 检测连接串含 `CHANGE_ME` 即抛 `InvalidOperationException`；由于 `ISqlSugarClient` 为懒加载单例，`Program.cs` 在启动期强制 `GetRequiredService` 激活一次，使错误在**进程启动时**暴露。

**涉及文件**：`src/Infrastructure/SqlSugarSetup.cs`、`Program.cs`。

**验证**：Production 环境无 `ConnectionStrings__PostgreSQL` 时启动即抛「ConnectionStrings:PostgreSQL 仍为 CHANGE_ME 占位符」；配置环境变量后正常启动。

### 八、前端：Monaco 本地化、路由代码分割、依赖清理

**问题**：

1. `@monaco-editor/react` 默认经 `@monaco-editor/loader` **运行时从 cdn.jsdelivr.net 拉取 monaco**，内网/离线环境编辑页不可用，违背单镜像自包含部署；
2. Monaco 体积大（MB 级）但被静态 import 进主包；
3. `zustand` 为死依赖（全项目无 import）。

**方案**：

1. 新增 `web/src/utils/monacoSetup.ts`（副作用模块，编辑页顶部 import）：`loader.config({ monaco })` 切换为本地打包实例。经核实 loader 源码，配置实例后 CDN 脚本注入分支不会执行（产物中的 jsdelivr 字符串仅为 loader 死配置常量）；Worker 无需手工配置——monaco-editor 0.5x 在打包器环境下通过 `new URL(..., import.meta.url)` 相对路径自举（基础 worker 走 `editorWebWorkerMain`，json/css/html/ts 语言 worker 走各自 workerManager），Vite 构建期静态产出独立 worker chunk。**注意不可自定义 `MonacoEnvironment.getWorker`，否则会覆盖内置自举**（monaco-editor 的 package.json exports 为严格子路径映射，`?worker` 导入与裸包名 `new URL` 均不可用，这是踩过的坑）；
2. 路由层将 `ConfigurationEditor` 改为 `React.lazy` + `Suspense` 懒加载：主包维持 1.44MB，Monaco（约 4MB）拆为编辑页专属 chunk 按需加载，各语言高亮模块亦自动按需分割；
3. 移除 `zustand` 依赖；新增 `monaco-editor@^0.56.0` 依赖与 `web/src/vite-env.d.ts`（Vite 客户端类型声明）。

**涉及文件**：`web/package.json`、`web/package-lock.json`、`web/src/utils/monacoSetup.ts`（新增）、`web/src/vite-env.d.ts`（新增）、`web/src/pages/configuration/ConfigurationEditor.tsx`、`web/src/router/index.tsx`；`wwwroot` 产物已随构建更新。

### 九、Dockerfile 加固

运行时镜像以镜像内置非 root 用户（`USER app`，UID 1654）运行；应用不写磁盘、8080 为非特权端口，无需额外权限。

### 新增配置项与错误码

| 配置项（appsettings / 环境变量） | 默认 | 说明 |
|---|---|---|
| `ClientAuth:ApiKey`（`ClientAuth__ApiKey`） | 空（不启用） | 非空时 `/api/client/*` 须携带 `X-Api-Key` |
| `RateLimiting:ClientPerMinute`（`RateLimiting__ClientPerMinute`） | 600 | 客户端拉取接口每 IP 每分钟请求上限 |
| `RateLimiting:LongPollConcurrency`（`RateLimiting__LongPollConcurrency`） | 200 | 长轮询接口每 IP 并发挂起上限 |

| 错误码 | 含义 | HTTP 状态 |
|---|---|---|
| 10003 | 客户端认证失败（X-Api-Key 缺失或错误） | 401 |
| 10004 | 触发限流（过于频繁 / 长轮询并发超限） | 429 |

### 客户端 SDK 兼容性说明

- 长轮询接口请求/响应结构不变；行为差异：变更感知从「最迟 2 秒」变为「即时」（另有 10 秒兜底复检、30 秒挂起上限不变）；
- 若服务端启用了 `ClientAuth:ApiKey`，SDK 需在 `/api/client/*` 请求上附带 `X-Api-Key` 头；
- 需正确处理两种新的非 200 响应：401（code 10003，Key 无效）、429（code 10004，建议退避重试）；
- 管理端接口（Portal）行为不变。

### 评审结论勘误

- 前次评审怀疑 `js-yaml: "^5.2.2"` 为不存在的版本号——**误判**，js-yaml 5.x 已发布（本地实际安装 5.2.2，`load/dump` API 兼容），未做变更；
- 原评审怀疑审计日志维度回填为 N+1 查询——**不成立**，`OperationLogRepository.LoadByIdsAsync` 已按主键批量加载，保持不变。
